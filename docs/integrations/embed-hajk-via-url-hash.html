Embedding Hajk via the URL hash

The host app shows Hajk in an <iframe> and controls the map by changing the hash part of the iframe's address.

How it works

Hajk keeps the map's state in the hash part of the address, i.e. everything after the #. The host app controls the map by changing that hash in the iframe's src. Hajk detects the change and updates the map without reloading the page. For example: 

// Send the state the map should have
function setMapState(params) {
  const iframe = document.getElementById("hajk");
  const url = new URL(iframe.src);
  url.hash = new URLSearchParams(params).toString();
  iframe.src = url.toString();
}

setMapState({
  m: "map_1",                                       // always include the current map
  z: "8",
  l: "background_layer_id,properties,detailed_plans" // full list of visible layers
});                                                 // Hajk zooms and shows the layers

Things to keep in mind:

  • Always include m (unless it is already in the query string, ?m=…). If the hash has no m, Hajk treats it as a map change and reloads on every update.
  • Send only the parameters that should change. Hajk compares each parameter with its current state and applies any that differ, so stale values, e.g. old x/y copied from the initial src, will undo what the user has done since.
  • Reading iframe.src gives the address the host app last set, not Hajk's current state. See Reading back below.

Live: Hajk reacts as soon as the hash changes

Param Controls Format and notes
m Which map is shown The map's name in Hajk. Changing it reloads all of Hajk; the other parameters in the hash are then applied as on a fresh start.
x, y Map center Coordinates in the map's projection, e.g. SWEREF 99. Always set both. The map pans smoothly to the point.
z Zoom level Integer (decimals are rounded). The map zooms smoothly to the level.
l Visible layers Comma-separated layer ids. The list is the complete set of visible layers: layers not in the list are hidden, including the background layer. The suffix _l, e.g. abc123_l, turns on labels for the layer (if it has a label style). An empty l= is ignored and does not hide anything.
gl Sublayers in group layers JSON stating which sublayers are visible in a group layer, e.g. {"groupLayerId":"sub1,sub2"}. Only needed when part of the group is visible; a group in l without an entry in gl shows all its sublayers.
p Open/close tools Comma-separated tool names in lower case, e.g. layerswitcher,search. Tools not in the list are closed; an empty string (p=) closes all tools. Anchor and Print are never controlled by p.
q Search phrase Fills in the search box and runs the search, using the search sources from s as they were at start.

Start only: read when Hajk loads

Changing these after Hajk has loaded has no effect. To apply a new value, the host app must also reload the iframe (or change m, which reloads Hajk).

Param Controls Format and notes
s Search sources Which search sources the search in q uses. It cannot be changed at runtime yet, so a live change of q uses the search sources that applied at start.
f CQL filter per layer URL-encoded JSON with layer id as key and CQL filter as value. Only features in the layer that match the filter are shown. Requires a WMS server that supports the CQL_FILTER vendor parameter, e.g. GeoServer.
clean Map without UI Hides tools, menus and other UI so only the map is visible. Useful when the host app provides all the UI itself. clean=false and clean=0 turn it off.
q_pc Property selection Property designation that the PropertyChecker tool looks up and highlights, with an address as fallback if address lookup is configured. Requires both PropertyChecker and the Search tool to be configured.

Prerequisite: live mode must be enabled

Without live mode Hajk reads the hash only when the map loads, and does not write its state back either. Live mode is enabled in one of two ways:

  • the enableAppStateInHash setting on the map in Hajk Admin, or
  • the enableAppStateInHash parameter in the address, for a single embedding. Put it in the query string (?enableAppStateInHash), not the hash: Hajk rewrites the hash and would drop it, so live mode would be lost after a map change (m) reloads Hajk.

By default every state change Hajk writes adds a browser history entry, so the Back button of the page hosting the iframe steps through map states. Enable replaceAppStateInHash on the map in Hajk Admin to replace the entry instead.

Reading back requires the same origin

When the user pans, zooms or toggles layers, Hajk writes its new state to the hash (shortly after the change, not instantly). If the host app wants to follow it, e.g. to save the state or sync it with something else in the app, it must be able to read the iframe's address.

The browser only allows that when the host app and Hajk have the same origin, i.e. the same protocol, domain and port. One way to achieve this is to put Hajk behind the same reverse proxy as the host app, e.g. https://app.example.com/map/.

  • Different origins: the host app can write to Hajk but not read back. That is enough when it only needs to control the map.
  • Same origin: both directions work, and the host app can listen for hashchange on iframe.contentWindow and read iframe.contentWindow.location.hash. Re-attach the listener on the iframe's load event, since a map change reloads Hajk.
